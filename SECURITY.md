# Reporting a security issue

Use the private vulnerability reporting option in the repository’s Security tab when GitHub offers it. Include the affected version or commit, platform, boundary that failed, and a minimal reproduction using files and processes you own. [GitHub Security](https://github.com/thisistuhinsen/workerOS/security)

If the private option is unavailable, open a public issue asking a maintainer for a private reporting channel. Keep reproduction details, credentials, file contents, and the names of affected systems out of that issue. Share them only after the maintainer confirms a private channel.

Reports about descriptor ownership, unauthorized delivery, ambiguous write effects, incorrect custody verdicts, and release integrity are in scope. Maintainers assess the affected versions and coordinate a fix and disclosure with the reporter. The latest published release is the starting point for fixes, and older versions may need an upgrade.
